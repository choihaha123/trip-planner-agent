  - **시간대가 '오전/오후/저녁'뿐이다.** 줄글 답변(평가 [7])보다 덜 구체적이다.
- **내용**
  1. 숙소 지역을 하나로 확정하게 한다(렌더러가 '/'·'또는' 숙소를 거절. R5-3과 같은 방식).
  2. 같은 날 장소들이 같은 권역인지 최소한으로 검사한다(예: KB 권역 태그). 기억된 선호(걷기 싫음 등)와 충돌하면 경고한다.
  3. 부분 수정은 지정한 일차만 다시 만들고 나머지는 이전 아티팩트를 재사용한다. '바뀐 점'은 빠짐없이 나열하고, 빠진 📌 자료도 알린다.
  4. 렌더러가 깨진 문자(한글 사이에 낀 숫자·비정상 음절 등)를 거절한다.
  5. 시간대에 대략적인 시각(예: 09:00~)을 넣을지 정한다.
- **완료 확인**: "2일차만 바꿔줘"에서 1·3일차가 그대로이고 이전보다 빨리 끝난다. 숙소가 하나로 정해진다. 📌 자료가 빠지면 안내가 붙는다.
- **정할 것**: 부분 수정 방식(일차 단위 재생성의 범위), 권역 검사 기준, 시각 표기 여부
- **참조**: SERVICE 2.2 · SPEC 2.2 · Phase 7 R5

### S6. 출처 품질·'출처 없음' 표시
- **문제**
  - **'(출처 없음, 사용자 확인 필요)' 표시가 들쭉날쭉하다.**
    - 붙지 말아야 할 곳에 붙는다: 환율 도구 환산 결과, 사용자가 준 금액을 깎는 조정안("하루 5만원 → 3.5만원").
    - 정작 필요한 곳에는 안 붙는다: 검색에서 온 숙소 가격(평가 [20]), USJ 성인 가격.
    - 관련 위치는 `src/tools.py:1015-1100`이다. 이러면 사용자가 표시 자체를 무시하게 된다.
  - **출처의 질이 낮다.**
    - 인스타 릴스를 식당 근거로 대고, 가이세키 페이지를 라멘·이자카야의 근거로 댄다(평가 [1]).
    - 본문에서 쓰지 않은 KKday·byfood 글까지 출처 목록에 들어간다.
    - 항공 출처 제목의 금액(109,314원)과 답변의 금액(258,000~374,000원)이 다르다.
    - 사용자가 보낸 유튜브는 거절하면서 검색으로 찾은 유튜브는 출처로 인용한다(평가 [20]).
  - **출처 작성일에 답하지 못한다.** "그 출처 언제 글이야?"에 "확인하기 어렵다"고만 하고 공식 사이트를 다시 찾지 않는다.
  - **확신하는 말투가 과하다.**
    - "출처 빼고 숫자만"에 설교조로 답했다(평가 [9]).
    - 계산하지 않은 비용까지 "충분할 것 같다"고 확신했다(평가 [2]).
- **내용**
  1. '출처 없음' 판정에서 환율 도구 결과와 사용자 입력에서 나온 금액을 확실히 제외한다. 검색 결과 금액은 빠짐없이 판정한다.
  2. 출처 목록에는 본문에서 실제로 인용한 것만 남긴다. SNS·영상 출처의 허용 규칙을 링크 수집 규칙과 맞춘다.
  3. 웹 검색 결과에 게시일이 있으면 출처 옆에 표시한다.
  4. 계산하지 않은 비용에 대한 단언을 금지하는 지시를 넣는다(필요하면 후처리 검사).
- **완료 확인**: 같은 평가 답변에서 환율·사용자 금액에는 표시가 없고, 검색 금액에는 출처나 표시가 빠짐없이 붙는다. 출처 목록에 본문에서 안 쓴 항목이 없다.
- **정할 것**: SNS·영상 출처 허용 여부, 게시일 표시 범위
- **참조**: SERVICE 2.3, 2.6 · SPEC 2.3, 2.6 · Phase 7 R1-3

### S7. 개인정보·운영 정리
- **문제**
  - **CLI는 인증 없이 누구의 데이터든 보고 지울 수 있다.**
    - `--user <아무 ID>`로 남의 자료와 기억을 볼 수 있다.
    - `--reset`은 확인 없이 바로 지운다(`main.py:46-59, 176-177`).
    - README에 로컬 전용 도구라는 전제가 적혀 있지 않다.
  - **웹에 계정 삭제·내 데이터 전체 삭제 기능이 없다.**
  - **외부 전송을 사용자에게 알리지 않는다.**
    - 질문 내용은 Tavily로, 글꼴과 html2canvas 요청은 jsDelivr CDN으로 나간다.
    - `trace.jsonl`에는 질문·답변 앞 200자가 user_id와 함께 쌓인다.
  - **로그 관리가 안 돼 있다.**
    - 로그 회전이 없어 `app.jsonl`이 이틀 만에 3.0MB, `trace.jsonl`이 1.8MB가 됐다.
    - 예외 로그 32줄에 AWS 계정 ARN이 남았다.
  - **만료 세션이 쌓인다.** 만료된 세션은 그 토큰으로 조회할 때만 지워진다.
  - **웹 보안 장치가 빠져 있다.** CSP·X-Frame-Options 헤더가 없고, CDN 스크립트·CSS에 SRI(integrity)가 없다(`src/web/static/index.html:8`, `app.js:708`).
  - **사소한 구멍**
    - URL 정규식이 대소문자를 구분해 `HTTPS://…`를 링크로 보지 않는다(`src/middleware.py:167`).
    - 테스트에서 닫지 않은 sqlite 연결 `ResourceWarning`이 찍힌다.
- **내용**
  1. `--reset`에 확인 질문(y/N)을 넣고, README에 CLI는 로컬 전용이라는 전제를 적는다.
  2. 웹 '내 데이터 전체 삭제'(계정 삭제 포함) 기능이 필요한지 정한다.
  3. 외부 전송과 로그 보관을 안내한다(README 또는 웹 화면).
  4. 로그 회전(`RotatingFileHandler`, 크기는 설정값)을 넣고, 로그에서 ARN 같은 계정 정보를 가린다.
  5. 만료 세션을 정기적으로 정리한다. 보안 헤더와 SRI를 추가한다.
  6. URL 추출을 대소문자 무시로 바꾸고, 테스트의 sqlite 연결을 닫는다.
- **완료 확인**: `--reset`이 확인 없이 지우지 않는다. 로그가 설정 크기를 넘으면 회전한다. 로그에 ARN이 남지 않는다.
- **정할 것**: 웹 데이터 삭제 기능 추가 여부, 로그 보관 기간·크기
- **참조**: SERVICE 2.9, 2.10 · SPEC 1장 설정값, 2.10
