## Phase 1. 기반

### Step 1. 환경·설정·Bedrock 연결
- **내용**
  - `.venv`에 `requirements.txt` 설치, `.env.example` 작성

  - `src/agent.py`: Bedrock(`ChatBedrockConverse`) 연결, 도구 없는 최소 `create_agent`, 매 턴 현재 날짜·요일·시간대 시스템 프롬프트 주입

### Step 2. CLI와 대화 기록
- **내용**
  - `main.py`: 대화 루프, `--user <user_id>`(기본 `default`, `__`로 시작하면 거부), `/new`
  - SQLite 체크포인터로 대화 기록 영구 저장, 실행 시 thread_id 생성·표시, `--thread <thread_id>`로 이어가기
  - thread에 만든 user_id 저장, 다른 user_id로 열면 거부
- **완료 확인**: 껐다 켜도 `--thread`로 대화가 이어지고, 다른 user로는 그 thread가 열리지 않는다.
- **시간 부족 시**: thread 소유자 검사를 Step 10으로 미룬다.
- **참조**: SERVICE 2.7 · SPEC 1.3(대화 기록), 2.7, 2.8

## Phase 6. 추후 추가 기능 (선택: 1차 완료·제출 후 시간 여유가 있을 때만)
> 1차 범위가 끝나기 전에는 시작하지 않는다. 순서대로 하나씩 하고, 각 Step의 '정할 것'은 시작 직전에 사용자와 정한다.

### Step 13. (선택) 장기 기억
- **내용**
  - user_id 단위 사용자 기억 저장소: 이름, 기본 출발지, 자주 가는 인원, 여행 선호 등. thread가 달라도 같은 user_id면 불러온다
  - 저장: 사용자가 직접 말한 정보만 저장(저장 여부·항목 판정은 파이썬 규칙 + 필요 시 LLM 추출), 다른 user_id 기억은 코드로 격리
  - 사용: 매 턴 시스템 프롬프트에 사용자 기억을 넣고, 정보 부족 처리(`check_trip_info`)의 기본값 후보로 쓰되 '기억한 정보'임을 밝힘
  - 확인·삭제: 사용자가 기억한 내용을 보고 지울 수 있게 하고(예: CLI 명령), `--reset`과의 관계를 정함
- **완료 확인**: alice가 thread A에서 "내 이름은 민수야, 보통 김포에서 출발해"라고 한 뒤, 새 thread B에서 이름과 출발지를 기억해 쓴다. bob의 thread에서는 보이지 않는다.
- **정할 것**: 저장 방식(후보: LangGraph Store — `ref/long_term_memory.py`의 `("users", user_id)` 네임스페이스 방식, 영구 저장 백엔드), 저장 항목 목록, 저장 시점(매 턴 자동 / 도구 호출), 확인·삭제 방법, 파일 위치(허용 파일 목록 추가 필요)
- **참조**: SERVICE 1.5, 2.2, 2.7 · `ref/long_term_memory.py`

### Step 14. (선택) MCP 서버
- **내용**: 에이전트 코어를 MCP 서버로 감싸 외부 클라이언트에서 호출. user_id는 서버 설정·인자로 받고 대화 내용으로 바꿀 수 없게 유지(SERVICE 2.8)
- **완료 확인**: MCP 클라이언트에서 질문하면 CLI와 같은 답(출처·도구 사용)을 받는다.
- **정할 것**: MCP 라이브러리(후보: `ref/mcp_server.py`의 fastmcp — 신규 라이브러리 승인 필요), 노출할 도구 범위(대화 전체 / 개별 도구), 실행 방식, 파일 위치
- **참조**: SERVICE 1.3 ② · SPEC 1.3 · `ref/mcp_server.py`

### Step 15. (선택) 웹페이지
- **내용**: 회원가입·로그인(로그인 유저 id = 에이전트 user_id), 대화 화면, 로그인 유저별 RAG 자료(수집 URL) 목록·삭제 화면. 일정표는 `render_itinerary`의 구조화 데이터(artifact)로 화면을 그림
- **완료 확인**: 로그인한 두 사용자가 각자 대화·자료를 쓰고 서로의 자료가 보이지 않는다.
- **정할 것**: 웹 프레임워크·인증 방식(신규 라이브러리 승인 필요), 비동기 처리 여부, 파일 구조
- **참조**: SERVICE 1.3 ③ · SPEC 1.3, 2.2(구조화 데이터)
