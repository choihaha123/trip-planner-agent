## 시나리오 1. URL 저장 → 새 대화에서 인용
1. user_id `alice`로 여행 블로그 URL과 함께 질문한다.
2. 미들웨어가 URL을 수집·판정해 `alice` 공간에 저장하고, 같은 턴 답변에 그 내용을 근거로 쓴다. 답변 끝 '※ 링크 처리 결과'에 '✔ 저장함: 제목 (URL)'이 표시된다. (질문 없이 링크만 보내면 저장 결과만 답한다)
3. 새 대화(새 thread_id)에서 같은 user_id `alice`로 관련 질문을 한다.
4. **기대 결과**: 답변이 해당 URL을 출처('페이지 제목 + URL')로 인용한다.

## 시나리오 2. 무관 URL 거절 + 사용자 격리
1. 여행과 무관한 URL과 함께 질문한다.
2. **기대 결과 (거절)**: 저장되지 않고 답변 근거로도 쓰이지 않으며, 답변 끝에 "여행 관련 내용이 아니라고 판단해 참고하지 않았습니다"가 안내되고, 로그에 거절이 기록된다.
3. 다른 user_id(예: `bob`)로 시나리오 1과 같은 질문을 한다.
4. **기대 결과 (격리)**: `alice`가 넣은 URL 콘텐츠가 검색·인용되지 않는다.

## 시나리오 3. 일정표 + 예산 초과 알림
1. "오사카 3박4일, 1인 100만원"으로 일정을 요청한다.
2. **기대 결과**: 일정을 바로 만들지 않고, 빠진 항목(인원·출발지)을 한 번에 묶어 되묻는다. (SERVICE 2.2)
3. "2명, 인천 출발"로 답한다. (또는 "알아서 해줘" → 다시 묻지 않고 '가정한 조건: 인원 1명, 출발지 인천'을 앞에 표시하고 진행)
4. **기대 결과**
   - 일자별·시간대별 장소, 이동수단·소요시간, 근거 출처가 포함된다.
   - 입장료 등 가격은 출처가 있으면 '제목 + URL'과 함께, 출처가 없으면 가격 옆에 '(출처 없음, 사용자 확인 필요)'가 붙어 표시된다.
   - 파이썬으로 계산한 항목별·일자별 합계(범위)와 환율 환산이 포함된다.
   - 비용 항목마다 근거(사용자 입력 / 출처 / 'LLM 추정치')와 대략치임이 표시된다.
   - 총액 범위를 예산과 비교해 예산 안 / 근접(±10%) / 초과를 알리고, 초과면 초과 금액을 알린다. 초과 금액이 예산의 15%를 넘으면 조정안도 제시한다. (2026-11-05 변경)

## 시나리오 4. 단발성 질문 + 날씨·환율
1. "A 관광지 아침에 사람 많아?"처럼 단발성 질문을 한다.
2. **기대 결과**: RAG 또는 웹 검색 근거로 출처와 함께 답한다.
3. 날씨·환율을 질문한다.
4. **기대 결과**: 실시간으로 조회한 값으로 답한다. 조회에 실패하거나 예보 범위 밖이면 대체 정보임을 표시하고 답한다. LLM 일반지식으로 답한 경우 '출처 없음, 사용자 확인 필요'가 표시된다.
