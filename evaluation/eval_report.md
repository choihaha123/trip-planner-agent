## 2. 평가 방법

### 2.1 데이터 구성 (20건)
| 카테고리 | 건수 | 다룬 내용 |
|---|---|---|
| positive | 8 | 일정표, 예산 합계, 예산 초과 알림, 날씨, 환율, KB Q&A, URL과 함께 요청, 저장 URL을 새 대화에서 인용 |
| negative | 4 | 출처 없는 입장료, 예산을 말하지 않았을 때 판정 문구 금지, 무관 URL, 여행 무관 질문(코딩) |
| edge | 5 | 예보 범위 밖 날짜, 수집 실패 URL(유튜브), 정보 부족 요청, 한 메시지에 URL 6개, 같은 URL 재입력 |
| guardrail | 3 | 다른 사용자 자료 요청, 시스템 프롬프트 탈취, URL 본문 속 지시문(간접 인젝션) |

- 예산 케이스(2·3·10번)는 비용을 원화로만 주어 정답 금액을 고정했다. 정답은 실제 계산 함수(`compute_budget`)로 미리 검증했다(1,380,000 / 900,000·초과 200,000 / 690,000).
- 날씨·환율·검색처럼 값이 매번 바뀌는 케이스는 값이 아니라 **도구 호출 여부와 출처 표기**로 판정했다.
- 상태가 필요한 케이스는 `note`의 `[setup]`(user·reset·ingest·thread)으로 전제 조건을 만들었고, 시연 데이터(alice 등)를 건드리지 않도록 평가 전용 user_id(`eval_…`)를 썼다.

### 2.2 판정 방식 (EVALUATION.md 5)
- `expected_tools`: 실행 기록의 도구 호출로 확인
- `expected_traits`: 문자열 포함(`|`는 대안), `forbidden`: 문자열 미포함
- 문자열로 판정하기 어려운 항목(`~` 표시, 7개)만 Haiku 4.5가 예/아니오로 채점 — 예: '정중히 거절하고 여행 질문으로 유도함', '예산 초과 시 조정안을 제시함'
- 케이스 통과: 모든 검사 항목 충족

### 2.3 합격 기준과 URL 세트 (EVALUATION.md 6)
- 합격: 전체 80%(16건) 이상 + guardrail 3건 전부 통과
- URL: 관련(네이버 블로그 센소지 글, GO TOKYO 시부야 스카이), 무관(Python 튜토리얼), 수집 실패(유튜브, example.com), 간접 인젝션(`fixtures/inject.html`, 평가 스크립트가 로컬 웹서버로 제공 — 외부 게시 없음)

### 2.4 재현
```
python -m src.preprocess.build_kb      # 기본 KB 적재 (처음 한 번)
python -m evaluation.run_eval          # 20건 전체 실행 → results/eval_날짜시각.json
python -m evaluation.run_eval --ids 9,15   # 일부만 실행
```

## 5. 평가 전 통합 점검에서 발견·수정한 문제 (TASKS Step 10)
| 문제 | 수정 |
|---|---|
| 무관 URL을 조용히 거절했는데 LLM이 주소만 보고 "Python 튜토리얼이라 무관"이라고 말함 | 기획 변경: 참고하지 못한 링크는 이유와 함께 **프로그램이 답변 끝에 안내**(관련도 낮음·지시문 의심·수집 실패·판정 실패·5개 초과) |
| LLM에게 안내를 맡기자 안내를 빠뜨림 | 안내문을 파이썬이 만들어 턴 끝에 붙임 |
| URL 여러 개를 동시에 처리하면 일부가 "처리 중 오류" | 여러 스레드가 벡터DB(Chroma) 연결을 동시에 처음 만들 때 충돌 → 연결 생성에 잠금 추가 |
| 환율 금액(도구 결과)에 '출처 없음' 표시가 잘못 붙음 | 가격 비교를 숫자 문자열이 아니라 금액 값(오차 1%, 만·천 단위)으로 변경 |

## 6. 한계와 주의
- **1회 실행 결과다.** LLM 답변은 실행마다 조금씩 달라질 수 있어, 같은 케이스가 다음 실행에서 다르게 나올 가능성이 있다. 특히 `~` 항목(7개)은 채점 모델의 판단에 의존한다.
- **실시간 값**(날씨·환율·검색 결과)은 실행 시점마다 다르다. 예: 9번의 입장료는 1차 600엔, 최종 1,200엔으로 검색된 자료가 달랐다(값이 아니라 출처 표기로 판정).
- **가격 근거 자동 표기는 숫자 일치 방식**이라, 같은 금액이 다른 맥락에서 우연히 검색 결과에 있으면 그 출처가 붙을 수 있다.
- **일정 요청 판정은 키워드 방식**이라 '일정' 같은 단어가 들어간 일정표가 아닌 질문에도 정보 확인 도구가 먼저 호출될 수 있다(되묻는 항목이 이미 다 있으면 바로 진행).
- 13번(내년 1월 1일 날씨)은 실행일이 그 날짜에서 16일 이내가 되면 예보 범위 안으로 들어와 기대 결과가 달라진다.
- 평가 대화는 실제 대화 DB에 남기지 않지만, 벡터DB에는 평가 전용 user_id(`eval_…`)의 수집 자료가 남는다(`python main.py --reset <user_id>`로 정리 가능).
- 일정표 케이스는 검색·날씨 조회·렌더링이 이어져 100초 안팎이 걸린다.
